# Bun Migration Design

Date: 2026-02-24

## Goal

Migrate memmem from Node.js/npm to Bun across all layers:
- Package manager: `npm` → `bun`
- SQLite driver: `better-sqlite3` → `bun:sqlite`
- Test runner: `vitest` → `bun test`
- Bundler: `esbuild` → `bun build`

## Motivation

- Faster test execution (current: ~39s)
- Simpler toolchain (fewer dependencies)
- Unified runtime/bundler/test-runner

## Approach: Staged Migration (3 phases)

Each phase ends with all tests passing before proceeding.

---

## Phase 1: `bun:sqlite` (replaces `better-sqlite3`)

### API differences

| better-sqlite3 | bun:sqlite |
|---|---|
| `new Database(path)` | `new Database(path)` |
| `db.prepare(sql).all(params)` | `db.query(sql).all(params)` |
| `db.prepare(sql).get(params)` | `db.query(sql).get(params)` |
| `db.prepare(sql).run(params)` | `db.run(sql, params)` |
| `db.exec(sql)` | `db.exec(sql)` (same) |
| `db.loadExtension(path)` | `db.loadExtension(path)` |
| `@types/better-sqlite3` | built into bun types |

### macOS sqlite-vec issue

Apple's default SQLite disables extension loading. Required workaround:

```typescript
import { Database } from "bun:sqlite";
Database.setCustomSQLite("/opt/homebrew/opt/sqlite/lib/libsqlite3.dylib");
```

This must be called before any `new Database()`. Linux/CI does not need this.

### Files to change

- `src/core/db.ts` — main database layer
- `package.json` — remove `better-sqlite3`, `@types/better-sqlite3`

### Verification

All 576 tests pass with `bun test` (or `npx vitest run` temporarily).

## Phase 2: `vitest` → `bun test`

### API differences

| vitest | bun test |
|---|---|
| `import { describe, it, expect } from 'vitest'` | globals auto-injected (no import needed) |
| `vi.fn()` | `mock(() => {})` from `bun:test` |
| `vi.mock('module', ...)` | `mock.module('module', ...)` |
| `vi.spyOn(obj, method)` | `spyOn(obj, method)` from `bun:test` |
| `vitest.config.ts` | `bunfig.toml` or CLI flags |

### Files to change

- All `*.test.ts` files — remove vitest imports, update mock APIs
- `vitest.config.ts` — delete
- `package.json` — remove `vitest`, `@vitest/coverage-v8`; update test script

### Verification

All 576 tests pass with `bun test`.

---

## Phase 3: `esbuild` → `bun build`

### API mapping

`bun build` CLI replaces esbuild programmatic API:

```bash
# CLI entrypoint (was: esbuild entryPoints src/cli/index-cli.ts --bundle --platform=node --format=esm)
bun build src/cli/index-cli.ts --outfile dist/cli-internal.mjs --target=node --external=@huggingface/transformers --external=better-sqlite3 ...
```

Or via `scripts/build.mjs` using Bun's JS API:
```typescript
await Bun.build({
  entrypoints: ["src/cli/index-cli.ts"],
  outdir: "dist",
  target: "node",
  external: ["@huggingface/transformers", "bun:sqlite", "sqlite-vec", "sharp", "onnxruntime-node"],
});
```

Note: `better-sqlite3` is removed by Phase 1; `bun:sqlite` is built-in and needs no external flag.

### Files to change

- `scripts/build.mjs` — rewrite using `Bun.build()`
- `package.json` — remove `esbuild` devDependency; update build script
- `scripts/conditional-build.sh` — `npm run build` → `bun run build`

### Verification

`bun run build` succeeds, `dist/` artifacts run correctly.

---

## Common changes (all phases)

- `package.json`: `engines.node` → `engines.bun`
- `CLAUDE.md`: update `npm` → `bun` instructions
- `package-lock.json`: delete; `bun.lockb` generated by `bun install`

## Risk register

| Risk | Likelihood | Mitigation |
|---|---|---|
| macOS `setCustomSQLite` path varies | Medium | Detect path dynamically or document setup |
| `bun test` mock API incompatibilities | Medium | Audit all `vi.*` usages before starting Phase 2 |
| `bun build` missing esbuild features | Low | esbuild config is simple; no plugins used |
| Native addon breakage | Low | `better-sqlite3` removed entirely in Phase 1 |
